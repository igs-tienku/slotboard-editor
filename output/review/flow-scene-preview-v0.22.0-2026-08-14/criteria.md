# 審核原則

每項滿分 100 分，所有項目都必須達到 85 分。平均分不能抵銷未達標項目；審核者必須先找可能失敗的反例，再引用凍結交付物與客觀檢查。

## [criterion:C1] 完整畫布預覽與尺寸適配

### Requirements / 要求

- 流程卡片預覽必須顯示 Scene 完整畫布範圍，不得裁切或拉伸。
- 預設卡片尺寸須依 Scene 原始長寬比調整，至少可合理區分橫版與直版。
- 預覽區是卡片主要視覺區，Scene 名稱、原始尺寸、圖層數與標註數可辨識。
- 任意合法卡片尺寸下仍維持完整預覽策略。

### Score anchors / 評分錨點

- 95–100：完整範圍、比例與資訊層級都有直接證據，多種尺寸皆有測試。
- 85–94：完整且不變形，至少橫版／直版適配有證據，僅有非阻斷微小瑕疵。
- 70–84：基本可看，但存在裁切、拉伸、預覽過小或尺寸適配不足。
- 40–69：多數 Scene 難以辨識，或只改大卡片而未處理比例。
- 0–39：仍是固定裁切縮圖、畫面缺失或功能不存在。

### Required evidence / 必須證據

- CSS `object-fit`、卡片預覽版面與 Scene 尺寸資訊的具體位置。
- 預設尺寸算法及橫版／直版測試結果。
- 檢查縮圖 SVG 的 `viewBox` 是否覆蓋完整 Scene 尺寸。

## [criterion:C2] 卡片縮放操作、持久化與 Undo

### Requirements / 要求

- 每張流程卡片有清楚且不干擾移動／按鈕的右下角縮放控制點。
- 縮放需補償流程 zoom，X/Y 靈敏度一致；Shift 可等比例。
- 尺寸限制必須避免過小不可用或過大失控。
- 尺寸寫入專案、重新開啟保留；單次拖曳只建立一筆 Undo，取消則還原。

### Score anchors / 評分錨點

- 95–100：互動、zoom、Shift、上下限、持久化、Undo／取消均有實作與測試證據。
- 85–94：核心操作可靠且可保存／Undo，只有非核心提示或邊界微瑕疵。
- 70–84：可縮放但手感、保存、Undo 或上下限至少一項明顯不足。
- 40–69：縮放與移動互相衝突、跳位，或重開即遺失。
- 0–39：沒有可用縮放。

### Required evidence / 必須證據

- 事件路由、縮放數學、root 歷史提交機制與模型更新位置。
- zoom 0.5、Shift、最大／最小尺寸的測試。
- serialize／deserialize 尺寸持久化測試。

## [criterion:C3] 連線幾何與自動排列一致性

### Requirements / 要求

- 連線起終點必須依每張卡片的實際寬高計算，縮放後即時跟隨。
- 自動整理需使用可變卡片尺寸，同行／同欄卡片不得因固定步距互相覆蓋。
- Scene 卡片原有移動、流程平移、連線標註拖曳／縮放仍可共存。

### Score anchors / 評分錨點

- 95–100：連線與排列皆以實際尺寸計算，分支、循環、不同尺寸都有直接測試或源碼證據。
- 85–94：核心幾何正確且無回歸，僅少數極端美觀問題。
- 70–84：一般情況可用，但可變尺寸下會重疊或連線偏移。
- 40–69：縮放後連線明顯錯位，或自動整理破壞流程。
- 0–39：流程主要操作無法使用。

### Required evidence / 必須證據

- 連線端點公式與 resize preview 更新鏈。
- 自動排列對欄寬、逐卡高度的計算及不重疊測試。
- 原有流程拖曳與平移測試仍通過。

## [criterion:C4] 相容性、效能與回歸安全

### Requirements / 要求

- 舊 schema v3 專案缺少卡片尺寸時自動補上合適預設，不破壞位置與連線。
- 既有 PSD、PDF、專案包、Scene 標註與圖層功能測試不得退步。
- 50 Scene × 100 圖層與真實 Canvas／PSD／PDF 效能基準通過。
- TypeScript、Lint 與建置零錯誤；Lint 不得留下 warning。

### Score anchors / 評分錨點

- 95–100：所有自動檢查通過且有舊檔遷移、效能與輸出證據。
- 85–94：完整回歸通過，僅有不影響交付的環境警示。
- 70–84：功能可用但缺少一類重要回歸或效能證據。
- 40–69：存在測試失敗、舊檔破壞或明顯效能退化。
- 0–39：無法建置或主要既有功能失效。

### Required evidence / 必須證據

- `npm run test`、`npm run lint`、`npm run benchmark` 結果。
- 舊 overview 無 width／height 的遷移測試。
- PSD 與 package 測試結果。

## [criterion:C5] 交付完整性與可維護性

### Requirements / 要求

- package、manifest、生成 Skill 與 Pages cache key 版本一致為 v0.22.0。
- README 清楚記錄功能、限制與操作方式。
- 尺寸算法集中於可測試函式，不應散落不可驗證的魔法計算。
- Git diff 無空白錯誤，審核交付物與客觀結果可追溯。

### Score anchors / 評分錨點

- 95–100：版本、文件、測試、算法與審核證據完整一致。
- 85–94：可維護且可部署，只有不影響使用的小型文件瑕疵。
- 70–84：功能存在但版本、文件或測試結構不完整。
- 40–69：交付難以追溯或維護，版本明顯不一致。
- 0–39：缺少主要交付物或版本不可部署。

### Required evidence / 必須證據

- 版本字串、README M22、可測試 helper、Git diff check 與凍結檔案清單。

# 一票否決條件

- 應用無法建置、頁面無法啟動或主要交付物缺失。
- 流程預覽裁切／拉伸 Scene，或卡片縮放無法保存。
- 卡片縮放造成 Scene 移動、流程平移、連線或 Undo 的核心操作失效。
- 任一完整測試、Lint 或效能基準失敗。
