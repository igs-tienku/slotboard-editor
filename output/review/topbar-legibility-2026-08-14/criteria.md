# 審核原則

每項滿分 100 分，所有項目都必須達到 90 分。平均分只供參考，不能抵銷未達標項目。

## [criterion:C1] 文字完整與按鈕尺寸

### Requirements / 要求

- Scene 與流程文字必須完整顯示，不得裁切、擠壓、換行或貼近邊界。
- 兩個按鈕使用同一尺寸規則，最小寬度至少 64px 且不超過 88px，水平內距至少 12px。
- 不得沿用原本套用於復原／重做圖示按鈕的 34px 固定寬度。

### Score anchors / 評分錨點

- 95–100：兩個標籤完整且留白均衡，尺寸規則明確、對稱並有防回歸證據。
- 90–94：文字完整可辨，尺寸符合上下限，僅有不影響使用的細微留白差異。
- 70–89：文字雖可讀但仍過窄、換行、邊界緊迫，或缺少可靠尺寸規則。
- 40–69：至少一個標籤明顯裁切或按鈕尺寸失衡。
- 0–39：模式切換按鈕缺失或無法辨識。

### Visual references / 圖文參考

![Chrome 修正前](assets/unqualified/chrome-topbar-before.png)

比較中央 Scene／流程按鈕；圖中為不合格例，文字被 34px 固定寬度壓縮。只參考缺陷位置與症狀，不模仿瀏覽器外框。

### Required evidence / 必須證據

- 指出 JSX 中兩個按鈕的專用 class。
- 指出 CSS 的最小寬度、內距與不換行規則。
- 指出自動測試如何拒絕回到 34px 模式按鈕。

## [criterion:C2] 狀態辨識與可存取性

### Requirements / 要求

- 啟用狀態維持高對比的亮色背景與深色文字，未啟用狀態保持淺色文字與深色背景。
- Scene／流程必須向輔助技術暴露目前是否選取；按鈕仍可正常點擊切換。
- 焦點、disabled 與復原／重做按鈕規則不得被模式按鈕的新樣式破壞。

### Score anchors / 評分錨點

- 95–100：視覺與語意狀態均明確，專用選擇器不污染其他控制項。
- 90–94：狀態清楚且具正確語意，只有極小且不影響操作的一致性差異。
- 70–89：狀態僅靠顏色或語意缺失，仍可操作但辨識性不足。
- 40–69：啟用與未啟用難以區分，或新規則明顯影響其他按鈕。
- 0–39：切換功能失效或文字與背景無法閱讀。

### Required evidence / 必須證據

- 檢查 `aria-pressed` 與原有 click handler。
- 檢查專用樣式及啟用狀態色彩規則。
- 搜尋新選擇器是否意外套用其他按鈕。

## [criterion:C3] 工具列空間與響應式穩定性

### Requirements / 要求

- 頂部三區 grid 架構維持不變，模式按鈕只取合理寬度，不為填滿空間而誇張伸展。
- 1050px 以下既有隱藏歷史區的規則保持有效；760px 以下既有最小寬度策略不變。
- 品牌、復原／重做、自動儲存與右側檔案操作不得因本修正被移除或改序。

### Score anchors / 評分錨點

- 95–100：修改局部、空間分配合理，兩個既有 breakpoint 與所有鄰接控制均有證據保持完整。
- 90–94：布局穩定且無明顯擠壓，僅缺少非關鍵尺寸的額外驗證。
- 70–89：桌面修正有效，但至少一個 breakpoint 或鄰接控制存在可見風險。
- 40–69：修正造成工具列明顯溢位、錯位或其他控制消失。
- 0–39：頂部工具列無法使用。

### Required evidence / 必須證據

- 指出 grid、breakpoint 與專用按鈕寬度規則。
- 指出 JSX 中工具列控制順序未變。
- 提供建置或靜態渲染檢查結果。

## [criterion:C4] 回歸驗證與可交付性

### Requirements / 要求

- TypeScript 建置、完整 Node 測試、PSD 驗證與 ESLint 全部通過。
- 新增針對模式按鈕 class、尺寸、內距、單行及選取語意的回歸測試。
- 版本更新為 v0.18.2，工作樹只包含本次相關修改與審核資料。

### Score anchors / 評分錨點

- 95–100：全部客觀檢查通過且回歸測試直接覆蓋本次根因與驗收條件。
- 90–94：全部檢查通過，回歸測試覆蓋主要根因但少一項次要防護。
- 70–89：功能可能正確，但測試不完整或有非核心檢查未通過。
- 40–69：建置、Lint 或完整測試存在失敗。
- 0–39：無法建置或交付物缺失。

### Required evidence / 必須證據

- 列出完整測試、Lint 與版本檢查結果。
- 指出新增測試的位置及實際通過數量。
- 檢查 Git 差異範圍。

# 一票否決條件

- 交付物缺失、無法建置或模式切換功能失效。
- Scene 或流程任一文字仍被裁切、換行或不可辨識。
- 任一審核項目低於 90 分。
